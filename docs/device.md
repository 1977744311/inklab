# USB 连真机

InkLab 可以通过 USB 或无线调试直接操作一副真实的 Rokid 眼镜。这是可选功能：普通启动不会调用 ADB，在工作台顶栏切到「USB 真机」时才启用。

能做的事：

- 一键把调试包推到眼镜上并打开；保存源码后自动再推一次。
- 在网页上用真实的触控板手势操作眼镜。
- 实时投屏、截原图、录视频，查看应用日志。
- 和模拟器并排对照，模拟器的引擎自动对齐眼镜上的 Ink 版本。
- 把模拟器的场景搬到真机上跑，生成两边的截图对照。
- 在调试包里模拟 IMU：回放录好的轨迹、从工作台实时下发，或者把真机读数录成轨迹给模拟器用。

## 准备

- 电脑装好 `adb` 和 `ffmpeg`（投屏解码用）。不在 `PATH` 里时，用环境变量 `ADB`、`FFMPEG` 指定路径。
- 「推到真机」要打包，需要本机能运行 `aiui` 命令（在 aiui-toolkit 里执行 `npm run install-cli`）。没装时也可以直接给打好的 `.aix`。
- 眼镜里打开 adb 调试，用 USB 连上电脑并允许调试。没打开时 `dumpsys`、`input` 等命令会被直接断开。
- 截图文字识别（OCR）用的是 macOS 自带的 Vision。在其他系统上照样能操作和截图，只是带文字检查（`expectText`）的场景会标成 `unsupported`。

## 五分钟上手

```bash
inklab <应用目录>       # 或 aiui dev app
```

1. 打开 <http://127.0.0.1:8788/>，点顶栏的「USB 真机」（或直接打开 `/device`）。
2. 只连着一副眼镜时会自动选上。「连接」卡片显示型号和眼镜上的 Ink 版本；有会影响测试的状态（比如没戴上），会逐条列出来。
3. 点「推到真机」：打包、装上调试包、打开应用、截一张图，一般 20 秒左右。
4. 点「开始实时投屏」看实时画面，用画面下方的「向后滑」「向前滑」「单击」「双击」「长按」操作眼镜。
5. 右侧「真机日志」显示应用自己的 `console` 输出。

之后每次保存源码都会自动推一次，不需要再点。

想一启动就进入真机模式并指定设备、输出目录：

```bash
inklab <应用目录> --device --serial <序列号> [--device-output DIR]
```

## 页面一览

左边是眼镜画面，右边是一组可以折叠的区块。

| 区域 | 用途 |
| --- | --- |
| 顶栏 | 显示当前选用的眼镜；浅色 / 深色切换和模拟器页共用 |
| 眼镜画面 | 「开始实时投屏」「截取原图」「录制视频」；投屏开着时用「实时视频 / 原图证据」切换两种画面；下面是五个触控板手势按钮，以及下载原图、下载录像的链接和「截图识别文字」 |
| 连接 | 选择眼镜（连着几副时在下拉框里选一副，点「选用」），显示设备信息和警告 |
| 推到真机 | 「推到真机」「只打开」「关掉助手」、选择打开哪一页、「保存源码时自动推送」开关，以及「眼镜上的调试包」列表 |
| 场景测试 | 选场景、「运行」「停止」「导出报告」；显示每一步、真实截图和报告位置 |
| 真机日志 | 按来源过滤：应用、运行时、引擎（默认不勾） |
| 模拟 IMU | 切换调试包里的传感器模式，见[模拟 IMU](#模拟-imu) |
| 语音调试 | 「发送文字并取图」「真实长按唤醒」，需要[设备适配器](#应用提供的设备适配器) |
| 支持范围 | 在这副眼镜和这个应用上，哪些能自动验证（按键、截图、文字注入、OCR），哪些不能 |

推到真机、场景测试、真机日志默认展开，其余默认收起；开合状态记在本机浏览器里。按钮的细节说明在悬停提示里。

**设备警告**：选中眼镜后，「连接」卡片会提示会让测试失真的状态：

- 佩戴检测判定没戴：触控板进入低功耗，手指操作不上报（InkLab 回放的手势不受影响）；
- 有无障碍服务在接管按键（比如 Quick Menu 会拦截长按镜腿）；
- AIUI 开发者模式没开（推送、打开时会临时打开，用完恢复原值）。

**自动选眼镜**：没指定 `--serial` 时，只连着一副眼镜就自动选上；打开页面时还没连上的，连上后几秒内自动选上。同一副眼镜 USB 和无线调试都连着时，选无线那个（这样录制途中可以拔线）。adb 服务重启后丢了的无线连接，会按 `inklab-device wifi` 记下的地址自动连回去。

## 推到真机

点「推到真机」会依次：打包（`aiui build`）→ 安装调试包 → 关掉 AI 助手，回收之前推送留下的旧实例 → 打开选中的页面 → 等第一帧 → 截图（画面还是黑的就等一会儿重拍）。旧实例在前台时一次推送约 17 到 20 秒。

- **保存即推送**：默认开启。被测工程是源码目录、而且选了设备时，保存源码会自动推一次；推送途中又保存的，推完后合并再推一次。要关掉，取消勾选「保存源码时自动推送」，或在应用的 `inklab.config.json` 里写 `"device": { "autoPush": false }`。
- **只打开**：不重新装包，直接打开已装好的调试包。
- **关掉助手**：连续真双击把 AI 助手整个关掉，助手里所有实例（包括推送留下的旧实例）一起销毁。为什么需要这一步，见[原理与实测](#原理与实测)。
- **眼镜上的调试包**：展开后列出开发者通道里的调试包，点「打开」直接打开（别的调试包从它 `app.json` 的第一页打开）。手机同步装的智能体放在系统私有目录，adb 读不到名字，不在列表里。

这是本机调试安装，和 Studio 发布是两回事，不能当作已经发布的证据。

### 调试包的身份

调试包的 ID 必须是 `develop.rokid.<业务>.<id>` 格式。默认按项目名生成 `develop.rokid.inklab.<项目>`（应用目录叫 `app` 时取上一级目录名，去掉 `aiui-` 前缀）；名字取 `app/AGENTS.md` 里的 Name，加上「（调试）」；权限按 `app.json` 补齐成 Studio 的写法。同一个 ID 重推时系统回执 `UPDATED`，不需要改版本号。

需要时在应用目录的 `inklab.config.json` 里覆盖：

```json
{
  "device": {
    "agentId": "develop.rokid.inklab.zhenghuo",
    "agentName": "整活派对（调试）",
    "page": "pages/index/index",
    "autoPush": true
  }
}
```

可写的字段：`agentId`、`agentName`、`agentPrompt`、`page`（默认打开哪一页）、`autoPush`、`permissions`、`inkVersion`、`nativeVersion`。

官方 `aix install` 装 `.aix` 时会改用包里写死的 ID，而 `aiui build` 每次打包的 ID 都不一样；所以 InkLab 用同一套安装协议，但保持固定 ID。

## 操作眼镜

- **触控板手势**：五个手势按钮直接往触控板设备写原始按键，系统收到的和手指操作完全一样。眼镜 10 秒熄屏，熄屏时第一个键只会点亮屏幕，所以每个手势前都会先确认屏幕亮着。没有触控板档案的设备退回 `input keyevent`，这时双击和长按做不了。
- **实时投屏**：眼镜端用 `screenrecord` 输出 `480×640` 的 H.264 视频流，本机 `ffmpeg` 解码后推到浏览器。画面下方显示帧率、刷新间隔和本机解码到渲染的耗时（不含眼镜编码和传输）。投屏画面经过 JPEG 压缩，只用来流畅预览；报告里的截图证据始终是另外截的无损 PNG。
- **截取原图**：用 ADB 截一张完整的 `480×640` 原始 PNG，画面下方给出下载链接；展开「截图识别文字」看 OCR 结果。
- **录制视频**：把浏览器里的投屏画面录成无声 MP4（不支持时退成 WebM），不增加眼镜的编码负担。录完自动存到 `<输出目录>/recordings`，单个文件上限 64 MiB，同时记下大小和 SHA-256。输出目录默认在系统临时目录的 `inklab-device-runs/` 下，用 `--device-output DIR` 指定。
- **真机日志**：实时显示眼镜上跟 AIUI 有关的日志，分三类：应用自己的 `console`、AIUI 运行时事件（打开、全屏、退回卡片等，压成一行）、Ink 引擎日志。推送结果和场景报告里会附上这段时间的应用日志、告警和错误。logcat 断了每 2 秒重连一次，从断开前最后一行的时间接着读，不重复也不漏。

## 真机 + 模拟器并排

在任一工作台的顶栏点「真机 + 模拟器」，或打开 `/device?simulator=1`。

- 模拟器的引擎自动对齐眼镜上的 Ink 版本：构建号一致的优先，其次是同一版本号（优先正式版），再次是同一版本线（major.minor）。
- 模拟器画面下方有方向键、确认、返回，以及只影响模拟器的「断网」「恢复联网」。联调多人应用时，让两边进同一个房间，用这两个按钮复测断线重连。
- 勾选「真机手势同步到模拟器」后，点手势按钮时模拟器也会收到触控板实际会发的那几个键（前后滑各带两个方向键）。

## 无线调试（不插线）

戴着眼镜录 IMU、走动测试时，数据线很碍事。眼镜和电脑连上同一个 Wi-Fi，插着线运行一次：

```bash
inklab-device wifi
```

它把眼镜的 adb 切到 TCP 模式（`adb tcpip 5555`），再通过 Wi-Fi `adb connect <眼镜 IP>:5555` 并核对连接，之后就可以拔线了。

- 插着线时，`adb devices` 里同一副眼镜有两行。只连着这一副时，所有 `inklab-device` 命令会通过 `ro.serialno` 认出是同一副，自动用无线那个，所以录到一半拔线也不会断。工作台里选 `IP:5555` 那一项。
- TCP 模式不持久，眼镜重启后回到只走 USB，要插线再运行一次。`inklab-device wifi --off` 关掉无线调试。
- 它不会替你开 Wi-Fi，也不会替你连网络（要输密码）。眼镜没连上 Wi-Fi 时会直接说明。
- 地址记在 `~/.cache/inklab/wifi-adb.json`。adb 服务重启（别的工具重启了它，或你手动 `adb kill-server`）会忘掉无线连接；之后命令发现一台设备都没有、或只插着这副眼镜的 USB 时，会按记下的地址自动连回去。
- 眼镜的日志缓冲区只有约 1 MiB，录 IMU 时大约只能保住最近一分钟。日志流断开太久，中间的读数就丢了；存轨迹时会报出哪个传感器有断档、最长多久，断档落在要用的段落里就重录那一段。

**连不上时**：长时间运行的 adb 服务可能卡住，表现为 USB 和 Wi-Fi 都列不出来，`adb connect` 报 `No route to host`，但 ping 和端口探测都通。这时运行 `adb kill-server` 再试。

## 命令行

不开浏览器也能操作眼镜。只连着一副眼镜时可以省略 `--serial`。

```bash
inklab-device info                                  # 型号、Ink 版本、对应的模拟器引擎、触控板档案和警告（有警告时退出码 2）
inklab-device push <app> [--page pages/x/index]     # 打包 → 安装 → 打开 → 截图（没显示到前台时退出码 2）
inklab-device open <app> [--page pages/x/index]     # 只打开这个工程的调试包
inklab-device open --agent <agentId> --page <页面>  # 按 ID 打开任意已装的智能体
inklab-device exit                                  # 连续真双击关掉助手，回收所有实例，并核对
inklab-device gesture <tap|double-tap|long-press|forward|backward|wake> [--hold-ms 1000]
inklab-device agents                                # 列出开发者通道的调试包
inklab-device wifi [--off]                          # 打开或关闭无线调试
inklab-device push <app> --imu replay --trace <轨迹名[#段落]> [--loop]   # 推模拟 IMU 回放包
inklab-device imu-record <app> --name <轨迹名> [--seconds 30] [--push]   # 录真机传感器读数存成轨迹
inklab-device imu-guide [<app>] [--name <轨迹名>]                        # 引导录制：眼镜上逐段提示动作
```

## 真机场景

```bash
inklab-device <app> --list                               # 列出能在真机上跑的场景
inklab-device <app> --scenario menus [--scenario …] \
  [--serial <序列号>] [--out /tmp/inklab-device-runs]    # 运行
```

连着几副眼镜时必须用 `--serial` 指定。原始截图和报告 `run.json` 默认存在系统临时目录的 `inklab-device-runs/` 下，`--out DIR` 指定别处。真机截图可能包含个人信息，建议放在不被 git 跟踪的目录里。工作台右侧的「场景测试」能跑同样的场景，实时显示步骤和截图。

真机场景有两个来源：

1. **模拟器的 `.mjs` 场景**（`<app>/e2e/scenarios/*.mjs`）会自动列出来。只用按键、等待、截图、长按唤醒的场景可以直接在真机上跑，方向键按触控板手势执行（前滑同时发右和下，和真机一致）。用到 `do` / `expect` 函数，或需要模拟器上下文（`build({ caps })` 等）的场景会标成不支持，并写明原因。

   跑完会在报告目录生成 `compare.html`：同名截图左边是模拟器的（先找 `e2e/baselines/<场景>/`，再找 `e2e/report/<场景>/`），右边是真机原图。场景里写的 `/app/…` 引入会映射回应用目录。

2. **专门写的真机场景**（`<app>/e2e/device-scenarios/*.json`），id 相同时优先于模拟器场景：

```json
{
  "id": "device-greeting-readonly",
  "title": "真实眼镜问候回复",
  "device": {
    "readOnly": true,
    "requires": ["asr-text", "screenshot", "ocr"],
    "steps": [
      { "shot": "before" },
      { "say": "你好" },
      { "expectText": {
        "anyOf": [
          { "all": ["你好"] },
          { "all": ["请问", "帮"] }
        ],
        "none": ["出错了"]
      } }
    ]
  }
}
```

| 步骤 | 在真机上怎么执行 |
| --- | --- |
| `press` / `pressMany` / `activate` / `back` | 发送真实按键，按真实时间等待。`waitMs` 指定每次输入后等多久（`pressMany` 对每一下都生效），不用模拟器的虚拟时间戳加速 |
| `wait` | 真实等待，最长 60 秒 |
| `say` | 发送 1–180 字节的 UTF-8 文字，需要应用在 `inklab.device.json` 里开启 `asrText: true` |
| `wake` | 长按触控板唤醒助手；可以先截图确认进入聆听状态，再接着 `say` |
| `shot` | 保存 ADB 返回的原始完整 PNG（不裁切、不合成背景），记下宽高和 SHA-256 |
| `expectText` | 用 macOS Vision 识别当前截图里的文字：`all` 必须全部出现，`none` 不能出现，`anyOf` 满足其中一组即可 |
| 模拟器专用的 `do` / `expect`、模拟硬件开关、LLM 录制 | 真机上不支持，运行前就标成 `unsupported` |

**结果和退出码**：

| 结果 | 退出码 | 含义 |
| --- | --- | --- |
| `passed` | `0` | 所有步骤成功，且至少有一条 `expectText` 文字检查通过 |
| `pending-review` | `2` | 只有按键和截图、没有文字检查的场景，要人工看截图确认 |
| `unsupported` | `2` | 缺少需要的能力（比如不在 macOS 上跑 OCR，或应用没开 `asrText`） |
| `failed` / `cancelled` | `1` | 步骤出错、文字检查超时没命中，或被手动停止 |

**文字检查会轮询截图**：真机上的对话气泡可能几秒后就消失，所以 `say` 之后不会死等，而是立刻开始轮询。`expectText` 默认 10 秒内最多截 12 次（间隔至少 500ms，用 `timeoutMs` 在 0 到 60000 之间调整），一旦识别出目标文字就通过；每次尝试的原图都会保留，到时间还没识别到才判失败。

## 模拟 IMU

眼镜是 user 版系统，没法用 adb 往 Android 传感器里注入数据，AIUI 也没有替换传感器的入口。所以 InkLab 在**调试包里**换掉传感器：

| 模式 | 眼镜上的传感器 | 用途 |
| --- | --- | --- |
| 真实（默认） | 真传感器 | 正常调试 |
| 回放 | 选中的轨迹（或其中一段）打进包里，传感器每次 `start` 都从头放；轨迹里没有的传感器照常用真数据 | 不戴眼镜也能复现「那一次」点头、深蹲 |
| 实时 | 通过 `adb reverse` 用 WebSocket 连回工作台，随时下发轨迹、注入故障、回到真传感器 | 边看画面边换动作；工作台要开着 |
| 录制 | 真传感器照常给应用，读数分批写进日志，InkLab 收下来存成轨迹 | 录真机数据给模拟器和回放用 |

在工作台右侧「模拟 IMU」区块（默认收起，标题旁显示眼镜当前的模式）里选模式，回放和实时模式再选轨迹和段落，然后点「切换并推送」。录制模式下可以「存成轨迹」（全部或最近 N 秒）、「打标记」；实时模式下可以「下发播放」「回到真传感器」「注入故障」。

调试包的名字会带上模式，比如「整活（调试·IMU 回放）」。你的源码不会被改动（做法见[原理与实测](#原理与实测)）。

轨迹存在工程的 `e2e/traces/<名字>.json`（多传感器、按真机时间戳、带段落和标记，格式见 `lib/imu-trace.mjs`）。模拟器里用 `await lab.imu.play('名字#段落')`，或者传感器卡片的「工程轨迹」播放同一批文件（见[使用指南](guide.md#传感器与-imu-轨迹)）。

**引导录制**：`inklab-device imu-guide <app>` 把 InkLab 自带的「IMU 引导录制」推到眼镜上，逐段提示动作：静止 30 秒、方向核对、正常 / 轻微 / 快速点头、低头看东西、摇头、左右看、歪头、说话、走动，最后 2 分钟静止（可以跳过）。

- 单击开始一段，向前滑跳过，向后滑重录上一段，双击退出。
- 每段先倒数 3 秒，倒数也录进去，作为动作前的静止段。
- 每段带「应该识别出几次」的标注，比如 `{ "nod": 5 }`，场景里可以直接拿来断言。
- 录完存成 `<app>/e2e/traces/guided-<时间>.json`。
- 读数是通过日志实时传回电脑的，全程要保持连接：插着线，或者先 `inklab-device wifi` 再拔线。

**限制**：

- 只换得掉应用自己 `new` 出来的传感器。World Awareness（`enableWorldAwareness` / `onHeadGesture`）用的是引擎内部的传感器，调试包里换不掉；不过它的识别逻辑在引擎里，模拟器和眼镜是同一份，可以用录下来的轨迹在模拟器里测。
- 每推一次新包都会新建一个实例。实时模式下，InkLab 会让旧版本的实例调用 `wx.exitMiniProgram()` 退出；录制时只收当前这一版的读数。

## 应用提供的设备适配器

InkLab 不内置任何产品专用的 ADB 控制脚本。有触控板档案的眼镜上，按键和长按唤醒由 InkLab 直接用真手势完成，适配器只需要负责**语音文字注入**（`say`），以及没有触控板档案时的按键和唤醒。没有适配器的应用照样可以用基础按键和截图。

在被测应用根目录建 `inklab.device.json`：

```json
{
  "profile": "my-app",
  "asrText": true,
  "controlScript": "scripts/glasses-control.mjs"
}
```

| 字段 | 含义 |
| --- | --- |
| `profile` | 写进报告的配置名，默认 `generic` |
| `asrText` | 是否支持注入语音识别文字。必须显式写 `true` 才允许执行 `say`；默认 `false`，这时带 `say` 的场景会在运行前标成 `unsupported` |
| `controlScript` | 控制脚本路径（相对于应用根目录），默认 `scripts/glasses-control.mjs` |

InkLab 这样调用控制脚本（单次超时 120 秒）：

```bash
node <controlScript> <command> [value] --serial <序列号> --wait-ms <毫秒> [--capture <PNG 路径>]
```

| command | value | 脚本要做的事 |
| --- | --- | --- |
| `key` | `left` `right` `up` `down` `enter` `back` `wake` | 用 ADB 给眼镜发对应按键 |
| `say` | 1–180 字节的 UTF-8 文字 | 把文字作为语音识别结果发给应用（只在 `asrText: true` 时调用） |
| `capture` | 无 | 截取眼镜当前屏幕的完整 PNG，写到 `--capture` 指定的路径 |
| `wake-assistant` | 无 | 模拟长按镜腿触控板，唤醒语音助手 |

脚本执行完要在标准输出打印一行 JSON 回执：包含 `"dispatched": true` 表示指令已发出（可以附带 `"note"`），否则算失败。回执只能证明「指令发给了设备」，不能证明界面正确响应了，所以报告里这一步的 `resultVerified` 记为 `false`，最终是否通过取决于之后的真实截图和文字检查。

## 原理与实测

下面是推送、手势、投屏背后的做法和实测结论，排查问题时有用。

### 安装与打开

- 安装走固件开发者接口 `content://com.rokid.aiui.develop`，和官方 `aix install` 是同一套协议：`prepare` 拿到收件目录 → 推送 `package.aix` 和 `agent.json` → `apply` → `status`。装好后再核对 `developer_manifest.json` 里的 MD5。
- 打开也走 `content://com.rokid.aiui.develop` 的 `open`，并从 AIUI 运行时日志确认它真的显示到了全屏。只看这次操作之后的日志：眼镜的日志缓冲只有 1 MiB，很快会被冲掉，不能靠更早的记录判断前台。

### 为什么推送前要关掉助手

- AIUI 同一时间只显示一个全屏应用，新打开的实例**不会顶掉**已经在前台的实例，自己的旧实例也一样。
- 每推一次新包都会新建一个实例，旧实例退回卡片后照样在跑（定时器、传感器、日志都在）。再打开同一个或别的应用、卸载调试包，都不会回收它。
- 只有从全屏连续双击三次才会回收：第一次退回卡片，第二次结束这一轮对话（`userExit`），第三次关掉助手（`dismiss clearModeData=true`）。这时助手里的所有实例一起销毁（日志里是 `Dropping Ink instance`）。
- 所以推送、「只打开」、`inklab-device exit` 都会先这样关掉助手，每一下都等日志确认走完这一步。助手本来没开就不双击。销毁了几个实例写在推送结果的 `reclaimed.dropped` 里。实测连推三次整活，每次都销毁了上一个实例。

**关助手没关成时的兜底**（比如应用弹了退出确认）：打开后等不到显示，就做一次真双击（应用收到返回）；看到前台开始退回，就等它退完（约 2 秒），排着的新实例会自动显示，等不到就重新打开一次；应用把返回当成「回上一层」时再双击，最多 4 次。退回过程中不会连续双击（那会把助手整个关掉，排着的实例也丢了），也不会替应用去点「退出吗？」的确认。实测整活、出招吧停在各自菜单、别的应用在前台、自己的旧实例在前台这几种情况下，都能显示出新包。

### 触控板手势的按键

时序取自实测，扫描码和来源设备都和手指操作一致：

| 手势 | 系统收到的键 |
| --- | --- |
| 每次接触 | 先发 `KEY_DASHBOARD`（系统里是 `KEYCODE_NOTIFICATION`） |
| 单击 | 约 0.5 秒后发 `ENTER` |
| 双击 | `BACK` |
| 长按 | `PROG1`（`KEYCODE_PROG_BLUE`） |
| 向前滑 | 同时发 `RIGHT` 和 `DOWN` |
| 向后滑 | 同时发 `LEFT` 和 `UP` |

### 投屏与清理

- Android 限制单次录屏时长，服务每 165 秒自动无缝重连一次视频流。
- 投屏期间只在没有操作时发临时唤醒信号防止熄屏，不会修改眼镜的常亮设置。
- 停止投屏、关闭网页、连接断开或退出服务时，InkLab 会清理这次启动的眼镜端 `screenrecord`、`logcat` 和本机解码进程。
- 本地服务只监听 `127.0.0.1`，所有设备控制请求都校验同源 Origin 和本次会话的 Token。

### 模拟 IMU 怎么换掉传感器

推送时把应用复制到临时目录，给用到 `AbsoluteOrientationSensor`、`Accelerometer`、`Gyroscope`、`Magnetometer` 的脚本开头加一行 `import`：同名导入会在模块里遮住引擎原生的类。直接给 `globalThis` 赋值改不到页面里写的类名（模拟器 0.20 / 0.21 和 RG1 上都实测过）。然后从临时目录打包，打完就删。`aiui build` 遇到带 `__inklab__/` 的包会拒绝，防止被当成发布包。

### RG1 实测

- 加速度计、陀螺仪请求 60Hz，实际给约 101Hz；姿态（Game Rotation Vector）请求 60Hz 给 60Hz，请求 10 或 30Hz 却给约 50Hz。偶尔有时间戳相同的重复读数。录制按真机时间戳原样保存，不重新采样。
- 没有磁力计：`Magnetometer` 的 `start` 返回 `OperationError`。
- `sensor.timestamp` 是开机以来的毫秒数，不是 `performance.now()`；姿态是相对的，静止时也不是单位四元数。
- 全屏应用在前台时屏幕不会熄（160 秒以上不碰触控板也亮着），录长时间静止段不用改熄屏设置。
- 无线调试（2026-11-18，Android 12 user 版）：`adb tcpip` 可用，电脑原有的调试授权直接有效，眼镜上不用再确认。Wi-Fi 下推送、手势、关助手都正常，截一张图约 0.6 秒。录制途中断开 adb 再重连，数据完整（33 秒加速度计 3339 条，101 Hz，无断档）。
